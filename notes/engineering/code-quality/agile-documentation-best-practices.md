## Context

Scott Ambler's comprehensive guide on agile documentation practices. The core principle: documentation is important, but only when it serves a clear purpose and audience.

**Source:** [Best Practices for Agile/Lean Documentation](http://www.agilemodeling.com/essays/agileDocumentationBestPractices.htm)

## Writing practices

**Prefer executable specifications:** Use tests as specifications rather than static documents. Tests serve two purposes: they specify the requirements and they validate your work.

**Document stable concepts:** Wait until information stabilizes before documenting. This reduces cost and risk since you won't waste effort revising unstable content.

**Generate system documentation:** Leverage modern tools to reverse-engineer code and automatically produce documentation rather than writing it manually.

## Simplification practices

- Keep it simple: a five-page document beats fifty pages if it achieves the goal
- Minimize overlap: write the fewest documents possible; build larger documents from smaller, focused ones
- Put information where customers need it, whether in code, diagrams, or external documents
- Share work openly to promote team communication and reduce documentation dependency

## Determination practices

- Only create documents that fulfill clear, important, immediate goals
- Work with actual users to identify minimal documentation requirements
- Let documentation consumers determine whether content meets their needs
- Ask stakeholders why they need documentation and how they'll use it before committing resources

## Timing practices

- Develop documentation evolutionarily; gather feedback and improve incrementally
- Consider whether conversation, mentoring, or active involvement works better than written documentation
- Base documentation on diagrams and artifacts your team actually maintains
- Update only when outdated information causes real problems

## Key principle

Treat documentation as a requirement: prioritize and estimate it like any other work item, making its creation an explicit business decision. Acknowledge that some documentation (user manuals, operations guides, system overviews) remains essential.
