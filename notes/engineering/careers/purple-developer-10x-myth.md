## Context

Jessica Kerr's concept of the "purple developer" reframes the 10x engineer myth. The most productive developer on a team is not inherently smarter; they are the one who built the system and therefore has the deepest mental model of it.

**Source:** [Purple Developer](https://jessitron.com/2020/12/26/purple-developer/)

## The core insight

What makes a software engineer productive? Experience with the language, intelligence, focus, a crafted IDE setup - these all matter. But the biggest factor by far is **familiarity with the codebase they are changing**.

This knowledge of what the system does and needs to do is completely essential and entirely contextual. The easiest way to get it is to create it, to write the software from scratch. When you have it, it does not feel like knowledge; it feels like breathing. It feels obvious.

## The purple developer problem

The purple developer has a deep mental model of the system because they built it. The blue and green developers have been assigned to help, but they cannot change the system effectively because they do not understand it. Meanwhile, purple may be changing the system fast enough that it is impossible for the others to build a mental model, no matter how smart they are.

Which developer in this picture is 10x more productive? Purple. But not because they are inherently smarter. Circumstances led to this situation.

## The solution

There is not a "productive" software engineer so much as "productive in this codebase." The solution is to work together on the system and invest attention in transferring the mental model. Spread the knowledge, spread the productivity.

## How to spot this

If one person on the team is dramatically faster than everyone else, ask whether they are genuinely more skilled or whether they simply have more context. If it is context, the fix is knowledge transfer, not hero worship.
