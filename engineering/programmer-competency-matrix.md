## Context

A structured framework by Sijin Joseph for assessing programmer skill levels across multiple dimensions. Useful for self-evaluation and identifying growth areas. Knowledge at each level is cumulative; being at level N means you also know everything from levels below N.

**Source:** [Programmer Competency Matrix](http://sijinjoseph.com/programmer-competency-matrix/)

## The framework

The matrix evaluates programmers on a 0-3 scale across 20+ skill categories, where each level represents roughly an order of magnitude increase in capability.

### Computer science fundamentals

- **Data structures**: From basic arrays and linked lists (level 0) through hash maps and sets (level 1) to B-trees, heaps, and tries (level 3)
- **Algorithms**: From simple sorting (level 0) through tree/graph algorithms (level 1) to dynamic programming and NP-problem recognition (level 3)
- **Systems programming**: From basic compiler understanding to full-stack architecture awareness

### Software engineering practices

- **Version control**: From folder-based backups (level 0) to distributed version control with branching strategies (level 3)
- **Build automation**: From manual builds to continuous integration and deployment pipelines
- **Testing**: From manual testing to comprehensive automated test frameworks with TDD

### Programming skills

- Problem decomposition and systems thinking
- Code organization from file-level to cross-system architecture
- Defensive coding and error handling
- API design and framework proficiency

### The underrated dimension

Communication is flagged as critical but often underweighted. The matrix explicitly tracks communication effectiveness as a competency area because project success depends on it as much as technical skill.

## How to use it

1. **Self-assessment**: Rate yourself honestly across all categories to identify gaps
2. **Development roadmap**: Compare your current level to your target level; focus learning on the biggest gaps
3. **Team calibration**: Use it as a shared vocabulary for discussing expectations without it becoming a rigid scoring system
4. **Interview framing**: Helpful for structuring technical interviews around competency areas rather than trivia

The key insight is that growth is exponential, not linear. Moving from level 1 to level 2 requires significantly more effort than 0 to 1. Plan accordingly.
