## Context

Lorenzo Pasqualis argues that "a software engineer is a problem solver first, and a coder second." Technical mastery matters less than the ability to decompose and solve complex problems systematically.

**Source:** [The 5 Problem-Solving Skills of Great Software Developers](https://dev.to/lpasqualis/the-5-problem-solving-skills-of-great-software-developers-4e6)

## The five skills

**1. Decompose large problems into smaller ones.** Break complex goals into manageable subgoals with clear dependencies. Focus on identifying what needs to be achieved (results) rather than how to achieve it (implementation). This abstraction layer enables flexibility in execution.

**2. Think in parallel.** Analyze task dependencies to identify opportunities for concurrent work. Understanding which activities can run simultaneously rather than sequentially improves efficiency and eliminates unnecessary bottlenecks.

**3. Abstract thoughtfully without over-engineering.** Abstract only use cases that you think will be required shortly. Balance flexibility with simplicity. Over-abstraction creates unnecessarily complex solutions for problems that do not yet exist.

**4. Reuse existing solutions.** Avoid reinventing functionality that is already solved. Evaluate available tools and frameworks before building from scratch, respecting time constraints and project scope.

**5. Visualize data flows.** Model systems as materials flowing through transformation steps. Represent processes as boxes (actions) connected by arrows (data pipelines), revealing bottlenecks and dependencies at a glance.

## Key takeaway

The distinction between junior and experienced engineers often reflects accumulated pattern-recognition and problem-decomposition expertise rather than language proficiency. Software development mastery requires deliberate practice over years.
