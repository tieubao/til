## Context

Henrik Warne curated programming quotes across three posts, analyzing which ones hold genuine wisdom versus which ones are witty but misleading. The collection spans debugging, software design, team dynamics, and the nature of programming itself.

**Source:** [The Wisdom of Programming Quotes](https://henrikwarne.com/2016/04/11/the-wisdom-of-programming-quotes/) | [More Good Programming Quotes](https://henrikwarne.com/2016/04/17/more-good-programming-quotes/) | [More Good Programming Quotes Part 2](https://henrikwarne.com/2017/09/16/more-good-programming-quotes-part-2/)

## On complexity and design

- "Bad programmers worry about code. Good ones worry about data structures." - Linus Torvalds. Foundation design matters more than implementation details.
- "For every complex problem, there's an answer that's clear, simple, and wrong." - H.L. Mencken. Elegance can mask poor solutions.
- "If you think good architecture is expensive, try bad architecture." - Brian Foote. Technical debt compounds faster than prevention costs.

## On debugging and testing

- "Debugging is like being a detective in a crime movie where you're also the murderer." - @fortes. You created the problem you are solving.
- "Program testing shows bugs exist, never that they don't." - Edsger Dijkstra. Testing has inherent limitations; absence of evidence is not evidence of absence.

## On teams and scaling

- "What one programmer can do in one month, two programmers can do in two months." - Fred Brooks. Team growth does not scale linearly; communication overhead increases complexity.
- "A distributed system fails when a computer you didn't know existed breaks yours." - Leslie Lamport. Complexity compounds in interconnected systems.

## On the craft

- "The act of describing a program in unambiguous detail and programming are one." - Kevlin Henney. Clear specification and implementation are inseparable.
- "Much of building a program involves debugging the specification." - Fred Brooks. Requirements clarification is as critical as writing code.
- "Programming teaches that asking right questions matters infinitely more than writing code." - @DanielMiessler. Problem definition precedes effective solutions.
- "If you can't explain it simply, you don't understand it well enough." - attributed to Albert Einstein. Clarity of explanation reveals depth of understanding.

## On software vs hardware

- "Hardware eventually fails. Software eventually works." - Michael Hartung. Given sufficient iteration, software problems are solvable.
- "You can accurately know what software will do, or when you'll get it, but not both." - @sanityinc. Software projects face inherent uncertainty in scope versus timeline.

## The meta-lesson

As Voltaire noted: "A witty saying proves nothing." Warne's key point is to critically evaluate programming wisdom rather than treating clever quotes as gospel. Some popular quotes (like the carpenter-woodpecker analogy) are misleading because they compare software to physical construction, ignoring that software is continuously adapted.
